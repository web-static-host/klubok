# RuStore: окно оценки и обновления внутри приложения

Как это сделано в «Списки.Заметки» (версия 1.0.6) — для повторения в нативном приложении на Kotlin/Compose.

Главный принцип: **ничего не всплывает во время работы.** Всё проверяется только при «запуске» приложения и показывается только на главных вкладках. Одновременно на экране максимум одна подсказка.

**«Запуск»** — это:
- холодный старт;
- возврат из фона, если приложение было свёрнуто **30 минут и больше**.

---

## 1. Подключение SDK

```gradle
// settings.gradle(.kts) → dependencyResolutionManagement.repositories
// Старый репозиторий RuStore отключён с 1 октября 2026, только новый адрес:
maven { url = uri("https://nexus-external.rustore.ru/repository/maven-rustore-exposed") }

// app/build.gradle(.kts)
implementation("ru.rustore.sdk:review:10.5.1")
implementation("ru.rustore.sdk:appupdate:10.5.1")
```

- `minSdk` — **23**.
- Оба SDK работают, только если приложение **установлено из RuStore** и пользователь **авторизован в RuStore**. В остальных случаях (debug-сборка, установка APK вручную) они возвращают ошибку. Её **молча игнорируем**, никаких сообщений пользователю.
- Окно обновления по-настоящему проверяется только на опубликованной версии: нужна более новая версия в RuStore.

## 2. Окно оценки (In-app Review SDK)

Системное окно RuStore со звёздами показывается **прямо в приложении**, без перехода в магазин.

### Когда показываем автоматически
| Показ | Условие |
|---|---|
| 1-й | пользователь добавил **≥ 10 элементов** (в «Списках» — пунктов; в напоминаниях — созданных напоминаний/событий) **и** пользовался приложением **минимум в 2 разных календарных дня** |
| 2-й и 3-й | прошло **≥ 30 дней** с прошлого показа **и** добавлено ещё **≥ 20 элементов** |
| дальше | никогда: **максимум 3 показа за всё время** |

Ограничения при показе:
- Проверка только при «запуске», через **2.5 с** после него, чтобы не наложиться на splash.
- Показываем только на главной вкладке. Если открыт экран сущности, поиск или приложение ушло в фон — пропускаем до следующего запуска.
- Если над нижним меню уже висит плашка «Обновление» или «Что нового», окно оценки в этот раз не показываем.
- Если SDK вернул ошибку **`RuStoreReviewExists`** (отзыв уже оставлен), больше никогда не показываем: счётчик показов = 3.
- Счётчик показов увеличиваем **до** вызова SDK. SDK не сообщает, поставил ли человек оценку, только что окно закрылось.
- **Самый первый запуск** (установка или первая версия с этой функцией) — только заводим счётчики, окно не показываем.

Что хранить (DataStore):
```
reviewInitialized: Boolean
reviewFirstUseDay: String      // "2026-10-06"
reviewItemsAdded: Int          // +1 при каждом добавлении элемента
reviewShownCount: Int
reviewLastShownAt: Long
reviewItemsAtLastShow: Int
```

```kotlin
private val reviewManager = RuStoreReviewManagerFactory.create(context)

fun requestReview(onError: (Throwable) -> Unit = {}) {
    // ReviewInfo живёт ~5 минут — запрашиваем непосредственно перед показом
    reviewManager.requestReviewFlow()
        .addOnSuccessListener { info ->
            reviewManager.launchReviewFlow(info)
                .addOnFailureListener(onError)
        }
        .addOnFailureListener(onError)
}
// В onError: если e::class.simpleName == "RuStoreReviewExists" → reviewShownCount = 3
```

### Ручной вызов
В настройках, раздел «О ПРИЛОЖЕНИИ», есть строка **«Оценить приложение»**. По тапу вызываем то же окно RuStore. Если SDK вернул ошибку — открываем карточку приложения в RuStore: `rustore://apps.rustore.ru/app/<package>`. Ручной вызов на счётчики автопоказа не влияет.

## 3. Обновление из RuStore (In-app Updates SDK, режим FLEXIBLE)

Новая версия скачивается **в фоне**, пользователь продолжает работать. Установка — по кнопке.

Поток:
1. При каждом «запуске» вызываем `getAppUpdateInfo()`.
2. Если `updateAvailability == UPDATE_AVAILABLE` — показываем плашку **«Доступна новая версия · Обновить»**.
3. Тап по плашке:
   - если в RuStore заполнено «Что нового» (`info.whatsNew`), сначала шторка «Доступна версия X.Y.Z» с этим текстом и кнопками **«Позже»** и **«Обновить»**;
   - если текста нет — сразу `startUpdateFlow(info, FLEXIBLE)`.
4. Пользователь согласился (`resultCode == Activity.RESULT_OK`) → плашка «Загружается обновление…», некликабельная. Прогресс приходит через `InstallStateUpdateListener`.
5. Статус `DOWNLOADED` (1) → плашка **«Обновление готово · Перезапустить»**. Тап → `completeUpdate(FLEXIBLE)`, приложение перезапускается уже новым.
6. Если при запуске `installStatus == DOWNLOADED` (скачалось в прошлый раз, но не установилось), сразу показываем «Обновление готово».

Ограничения:
- **«×» на плашке «Доступна новая версия», «Позже» или минута на экране** → не предлагаем **3 дня**. Храним `updatePromptSnoozedUntil`.
- «×» на «Загружается» / «Обновление готово» скрывает плашку только до следующего запуска.
- `AppUpdateInfo` одноразовый: перед `startUpdateFlow` каждый раз берём свежий.
- Любая ошибка SDK — молчим.

```kotlin
private val updateManager = RuStoreAppUpdateManagerFactory.create(context)
private val flexible = AppUpdateOptions.Builder().appUpdateType(AppUpdateType.FLEXIBLE).build()

updateManager.registerListener { state -> onInstallStatus(state.installStatus) } // unregister в onDestroy

fun checkUpdate() = updateManager.getAppUpdateInfo()
    .addOnSuccessListener { info ->
        when {
            info.installStatus == InstallStatus.DOWNLOADED -> showReadyToInstall()
            info.updateAvailability == UpdateAvailability.UPDATE_AVAILABLE && !snoozed() ->
                showUpdateAvailable(info.availableVersionName, info.whatsNew)
        }
    }

fun startUpdate() = updateManager.getAppUpdateInfo().addOnSuccessListener { info ->
    updateManager.startUpdateFlow(info, flexible)
        .addOnSuccessListener { code -> if (code == Activity.RESULT_OK) showDownloading() }
        .addOnFailureListener { snoozeUpdate() }
}

fun completeUpdate() = updateManager.completeUpdate(flexible)
```

## 4. «Что нового» после обновления

После того как человек обновился, над меню один раз появляется плашка **«Что нового в версии X.Y.Z»**.

- Определение: при «запуске» сравниваем текущую `versionName` с сохранённой `lastSeenVersion`.
  - Текущая новее → показываем.
  - `lastSeenVersion` нет → показываем, только если у пользователя уже есть данные (обновился с версии без этой функции). **Свежая установка — не показываем.**
- Тексты берём из того же списка изменений, что и «О приложении». Если для версии пунктов нет — не показываем.
- Тап → шторка «Что нового в версии X.Y.Z»: маркированный список и кнопка-градиент **«Понятно»** во всю ширину.
- Плашка пропадает после тапа, после «×» или сама: суммарно **1 минута на экране** либо **3 запуска**.

## 5. Плашка над нижним меню — общий вид и приоритет

Одна «таблетка» над нижним меню (дизайн — раздел 7.21 DESIGN_SYSTEM.md):
- по центру, на 8 dp выше меню;
- `glass-strong`, круглая;
- слева кружок 24 dp с градиентом и белой иконкой 13;
- текст 12/600, действие 12/700 акцентным цветом;
- справа «×» 28 dp.

| Состояние | Иконка | Текст |
|---|---|---|
| Обновление скачано | `RefreshCw` | «Обновление готово · Перезапустить» |
| Скачивается | `Download` | «Загружается обновление…» (некликабельна) |
| Доступна версия | `Download` | «Доступна новая версия · Обновить» |
| После обновления | `Sparkles` | «Что нового в версии X.Y.Z» |

- **Приоритет** (показывается одна, верхняя по списку): готово → скачивается → доступно → что нового.
- Удалённое объявление (если есть) важнее всех: пока оно на экране, плашки не показываются.
- Показывается только на главных вкладках. В открытой сущности и в поиске её нет.
- Окно оценки не показывается, пока на экране любая плашка.

## 6. Удалённое объявление (для пользователей старых версий)

Плашка обновления появилась только в 1.0.6, у старых версий её нет. Для них в приложении с первой версии есть **баннер объявлений из удалённого JSON**: файл на GitHub raw, читается при запуске с таймаутом 5 с и кэшируется.

- Поля: `enabled`, `title`, `message`, `buttonText`, `urls.rustore` (+ `fallback`), `targetVersion`, `dismissible`.
- `targetVersion` — показывать только версиям **ниже** указанной.
- Закрытие крестиком запоминается по паре `targetVersion` + `title`.

**Советую заложить это в новое приложение с первой версии.** Тогда можно будет сообщить что угодно даже тем, кто не обновляется.
