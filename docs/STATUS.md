## Сайт работает на базе Supabase (сделано 8 октября)
Проект: `https://exjpqpmfdumjqzgehtpg.supabase.co` (Central EU). Адрес и открытый ключ — в `.env`, подключение — `src/supabase.ts`, все запросы — `src/store.tsx`.

Ограничения теста:

- Ссылку из письма открывать в том же браузере/телефоне, где просили вход (иначе просто запросить снова).

## Концепция «всё на картинке» (сделано 8 октября)
- Пост = 1–10 картинок + название + категория. Описания, ингредиентов, шагов нет. Особый вид — «До и после» (две картинки рядом).
- Картинки листаются, по нажатию — на весь экран с увеличением. Картинки не обрезаются.
- Обычных комментариев нет; на отзыв «Я попробовал» можно ответить (до 500 знаков), у автора поста — метка «автор». Автор не может отметить «Я попробовал» у своего поста (и на сайте, и в базе).
- В базе: `supabase/migrations/002_picture_posts.sql` (обновление без потери данных), таблица `try_replies`, скрытые поля `ai_tags`, `ai_text` для ИИ.
- Иконка сайта во вкладке: `favicon.ico`, `favicon-32.png`, `apple-touch-icon.png`.

## Вход по паролю и автопроверка (сделано 8 октября)
- Вход: почта + пароль (от 8 символов), регистрация, «Забыли пароль?» (письмо со ссылкой → окно «Новый пароль»). Вход по ссылке убран.
- Правила — страница `#/rules` (`src/pages/Rules.tsx`), ссылки из регистрации, создания поста, профиля.
- Всё, что пишут пользователи (пост, отзыв, ответ, профиль), идёт через серверную функцию `supabase/functions/publish`:
  1) быстрые проверки: ссылки и их маскировка («точка ру», «t . me», пробелы), телефоны, почта, мат (в т.ч. «х.у.й», «xyй»);
  2) GigaChat (модель GigaChat-2-Max): текст и каждая картинка по правилам, «нет людей», текст с картинки, скрытые слова → `ai_tags`, `ai_text`;
  3) запись в базу. Напрямую с сайта писать в эти таблицы нельзя (`migrations/003_checked_publish.sql`).
- ИИ недоступен — пост проходит только быстрые проверки и помечается `checked_by_ai = false`.
- Секрет `GIGACHAT_AUTH_KEY` (ключ авторизации GigaChat) — только в Supabase → Edge Functions → Secrets. Проверка связи: `…/functions/v1/publish?check=1`.
- Для GigaChat нужен корневой сертификат Минцифры — он вшит в функцию. Если хостинг Supabase его не примет (проверка покажет ошибку сертификата), запасной вариант — Yandex AI Studio.

## Регистрация, профиль, аватар (сделано 8 октября)
- При регистрации: имя или название (до 50 символов) и уникальный ник (@, латиница, цифры, _). Перед регистрацией функция `publish` (действие `check-profile`) проверяет правила и занятость ника. Ник к почте не привязан.
- Поля «Город» больше нет (`migrations/004_signup_name_handle.sql`).
- Аватар: загрузить фото → редактор в окне поверх профиля (`src/components/AvatarCropper.tsx`), в цветах темы: фото целиком, квадратная рамка с кругом — двигать, тянуть за углы, колёсико/два пальца меняют размер; линейка наклона ±45°, поворот на 90°, отражение, «Цвет» (яркость, контраст, насыщенность), «Сбросить» → квадрат 256×256 (~13 КБ); или убрать.
- «Новая идея»: картинки можно перетаскивать в окно и вставлять Ctrl+V. Проверяется по правилам, люди на аватарке разрешены. Старое фото удаляется.
- Пароли хранит Supabase Auth в виде хэша bcrypt — посмотреть пароль не может никто, включая владельца. На своём сервере будет так же (bcrypt/argon2).
- Правила на сайте — без упоминания ИИ.

## Проверка картинок в фоне (сделано 8 октября)
- Картинка загружается и проверяется сразу после выбора (`src/components/useCheckedImages.ts`, действие `check-image` функции `publish`). На миниатюре: «Проверяем…», ✓ или красная пометка с причиной. При публикации проверенные картинки повторно не проверяются (результаты — таблица `image_checks`, `migrations/005_image_checks.sql`).
- Нажали «Опубликовать» во время проверки — публикация начнётся сама, когда проверка закончится.
- Ложные срабатывания: «телефоном» считались номера шагов и граммовки подряд — теперь телефон только в формате +7/8 и группами цифр; текст с картинки проверяется только на явные ссылки (http, www, site.ru, t.me) и мат. ИИ получил точное определение «людей» (лицо или фигура; руки, еда, иконки — нет; сомневаешься — нет).

## Подробная раскладка идеи от ИИ (сделано 8 октября)
- Для любых картинок (рецепты, лайфхаки, интерьеры, рукоделие, сад…) ИИ раскладывает идею по полочкам: идея одной фразой, вид, главное, способы, инструменты, повод/время/место, характер/стиль, похожие темы, сложность, время. Это основа будущих рекомендаций.
- То, что есть почти везде (соль, перец, вода, сахар, масло, мука, специи, посуда, руки…), в теги не попадает: ИИ просят их не писать, и функция дополнительно вычищает их списком `STOP`.
- Хранится в `posts.ai_meta` и `image_checks.meta` (`migrations/006_ai_meta.sql`). Плоский список для поиска — по-прежнему `ai_tags`. Старые посты остаются со старыми словами; новые публикации получают раскладку.

## Правило «без людей» уточнено (9 октября)
- Нельзя: люди на фото и нарисованные (в том числе мультяшные, аниме, иллюстрации). Можно: руки в кадре; персонажи-не-люди — ожившая еда и предметы с лицами, мультяшные животные, маскоты, игрушки; иконки и человечки-значки. Так в запросе к ИИ, в правилах на сайте и в CLAUDE.md.
- ИИ не отвечает «есть люди: да/нет», а выбирает, кто на картинке (`who`): никого / только руки / персонаж-не-человек / нарисованный человек / человек на фото. Отказ — только за «нарисованный человек» и «человек на фото»; причины ИИ «есть человек» при выборе «персонаж-не-человек» отбрасываются (только у картинок — у текста «оскорбление людей» остаётся нарушением). Повод: ИИ принимал картошку в плаще за человека.
- Причины отказа от ИИ показываются без служебных слов (`humanReason`): «people = true» → «На картинках не должно быть людей (руки в кадре можно)», прочее служебное убирается.
- ИИ иногда «за компанию» переписывал в причины строчку из списка правил (например, «мат и грубая брань» на картинке без текста). Теперь в задании: причину писать только с тем, что реально есть на картинке, с цитатой («мат: „…“», «ссылка: „…“»). Если ИИ всё же переписал строчку правил без цитаты — сайт её отбрасывает (`isRuleCopy`).
- Цитату мата из ответа ИИ человеку не показываем: причины про мат и брань заменяются на «Нецензурная брань запрещена», про оскорбления — на «Оскорбления запрещены» (`humanReason`). Цитата нужна только серверу — отличить настоящую находку от переписанного правила.
- Текст с картинки ГигаЧат переписывает отдельной просьбой «перепиши дословно весь текст» (`readText`) — в фоне после публикации, после раскладки на теги; мат и ссылки в этом тексте ищет наш список слов. Нашёл — идея скрывается, картинка помечается плохой. Опыт 9 октября (GitHub → Actions → «Опыт — чтение надписей ГигаЧатом»): на вопрос «есть ли мат?» ГигаЧат отвечает «нет», даже когда видит слово, а переписать текст — переписывает всё, включая мелкую надпись от руки; внутри общего разбора переписывал только заголовок. Поэтому из раскладки на теги поле «текст» убрано.
- Перепроверка старой идеи: GitHub → Actions → «Перепроверка идеи» → id идеи (действие `admin-recheck`, в журнал — только «скрыта / нет» и замеры).
- Плашка «Оригинал» на странице идеи убрана: сайт не проверял, что идея своя, а ставил её всем — пират выглядел бы «оригиналом». Позже: поиск копий внутри «Клубка» при загрузке и жалоба «Это моя картинка».
- Живые обновления (Supabase Realtime, `supabase/migrations/012_realtime.sql`, подписки в `src/store.tsx`): новые отзывы и ответы появляются у всех сразу; своя идея сама получает теги или «Скрыто» с сообщением о причине — без перезагрузки. Соединение идёт через проброс: в nginx добавлен блок `/api/realtime/` (см. `docs/PROXY.md`), проверено — сервер отвечает «101 Switching Protocols».
- Скрытая идея в ленте автора: картинка серая и бледная, перечёркнута красным крест-накрест, по центру — «Скрыто» и причина. Убраны тонкие дуги по углам всех карточек (оставался отступ рамки «только что опубликовано» — теперь он есть, только пока рамка видна).

## Уменьшенные копии для ленты (сделано 9 октября)
- При загрузке картинок идеи сайт делает ещё копию 600 px в ширину (JPEG 0,85, `shrink` в `src/lib.ts`) и кладёт рядом: `<имя>_s.jpg` (`Img.thumb`). Карточка в ленте — до ~270 точек, на чётких экранах до ~540 px, так что 600 хватает без потери качества. Картинки не шире ~660 px копию не получают.
- Лента, миниатюры, обложки папок, «до и после» (`Picture` с `w ≤ 600`) берут копию; страница идеи и увеличение — оригинал. Копия не загрузилась — сразу оригинал.
- Пример: картинка 1198 px — оригинал 353 КБ, копия 125 КБ. Тестовые картинки (~640 px) копий не получают — им не нужно.
- Старые картинки: GitHub → Actions → «Копии картинок для ленты» → Run workflow (`.github/scripts/thumbs.py`): скачивает картинки без копии, шире ~660 px уменьшает (Pillow, Lanczos, JPEG 85) и отдаёт функции `publish` (действие `admin-thumb`, пускает только с ключом доступа Supabase из секретов GitHub) — она кладёт копию и прописывает её в идеи.
- Сделано для старых идей 9 октября: из 39 картинок 17 шире 660 px получили копии; их вес в ленте 2684 → 1681 КБ (у больших — в 2–3 раза: креветки 353 → 116 КБ, салат 225 → 88 КБ). На вид в карточке — как оригинал.
- Сервер принимает копию только из папки автора; копии первых двух картинок (их видно в ленте) ИИ проверяет в фоне после публикации — подсунуть в ленту другое нельзя. Удаление идеи удаляет и копии. Только для новых публикаций.

## Проверка картинок в две части (сделано 9 октября)
- Замеры показали: время ответа ГигаЧата почти целиком зависит от того, сколько он пишет (~0,05 с на токен): салат 221 токен — 10 с, креветки 391 — 23 с. Картинки проверяются по одной — у личного тарифа ГигаЧата один поток (одновременно — только у тарифа для юрлиц и ИП).
- Быстрая проверка (`aiCheckImage(..., 'quick')`) — сразу при загрузке: можно ли по правилам (ссылки, ники, телефоны, QR на картинке — нарушение), есть ли люди, название, категории. Короткий ответ.
- Подробный разбор (`'full'`, `describePost`) — после публикации, в фоне (`later` → `EdgeRuntime.waitUntil`): весь текст с картинки и раскладка для поиска и рекомендаций; не дольше ~100 с. Строгая проверка текста с картинки (ссылки, мат): нашлось — идея скрывается (`posts.hidden`, `hidden_reason`, `migrations/010_hidden_posts.sql`), её видит только автор с пометкой «Идея скрыта» и причиной; в ленте, поиске, подписках её нет.
- Название и категории при публикации — только быстрые правила (ссылки, мат), без ожидания ИИ; ИИ проверяет их уже после публикации, в фоне (`describePost`, первым делом): нарушение — идея сразу скрывается с причиной «Название или категории: …». Публикация — около секунды вместо ~9.
- После публикации — переход в профиль (уже в профиле — окно просто закрывается); новая идея первой в «Публикациях», 3 секунды в бирюзовой рамке (`fresh` в store).
- ГигаЧат «занят» (429, например идёт фоновый разбор прошлой идеи) — запрос повторяется до ~60 с (`gcFetchWait`).
- Миниатюры в форме: крестик — убрать; перетаскивание мышкой и пальцем (свои события указателя, а не браузерное перетаскивание): тянешь — остальные раздвигаются на ходу, можно в любое место. Выбранная картинка запоминается по ключу, а не номеру, — после перестановки остаётся выбранной. «До и после» в форме — с подсказкой «Первые две картинки — до и после. Далее добавьте ещё хотя бы одну картинку» — переключатель по DESIGN_SYSTEM 7.15 (`Toggle` в `ui.tsx`).
- Проверка связи (GET функции `publish`) показывает и список моделей ГигаЧата, доступных по ключу.

## Форма создания идеи и подбор категорий (сделано 9 октября)
- Форма как страница идеи: на компьютере картинки слева, название, категории и «до и после» справа; на телефоне — друг под другом. Слева — большая картинка (выбранная) и ряд миниатюр; размер окна не меняется, когда добавляются картинки (картинка ниже ровно на ряд миниатюр).
- Пока картинка не проверена (или её нет), поля названия и категорий заблокированы — подбор и правка не спорят; открываются, как только проверена первая картинка.
- Замеры проверки картинки (сводка в форме убрана по просьбе владельца) пишутся в `image_checks.timing` (`migrations/008_check_timing.sql`); последние 25 — GitHub → Actions → «Замеры проверки картинок» → Run workflow (в журнале только числа).

## «До и после» (сделано 9 октября)
- Формат остаётся. При создании: галочка «До и после» (видна от 2 картинок) — 1-я картинка «до», 2-я «после», и обязательно ещё хотя бы одна (как сделали). Меньше 3 картинок — не публикуется (проверка и на сайте, и в функции `publish`).

- На странице идеи (`Gallery.tsx`): первый слайд — «до» и «после» рядом, обе целиком (без обрезки), дальше листаются остальные.

Высота слайдов — между парой и первой картинкой с шагами, чтобы картинки с текстом не мельчали. Нажатие — просмотр каждой картинки на весь экран.

## Загрузка без «фантомов» (сделано 9 октября)
- Страницы больше не ждут данных: шапка, полоска категорий, шапка профиля и кнопки рисуются сразу. Серым мигают только места под данные — своя заглушка у каждой страницы (`src/components/Skeleton.tsx`): лента — те же колонки и отступы, что у `Masonry`, с местом под название и автора; профиль, страница идеи, подписки, папки, поиск — по своей разметке.
- Заглушки повторяют настоящую разметку буквально: текст — серые полоски внутри строк с теми же шрифтами (`Line`), поэтому высоты строк совпадают. Названия в ленте — 1 или 2 строки по ширине колонки; на телефоне у страницы идеи название и подпись автора в несколько строк. Заглушки не короче экрана — полоса прокрутки не появляется вдруг и не сдвигает страницу. Замеры: положение и ширина всего совпадают до пикселя; отличается только высота картинок (их пропорции приходят вместе с данными).
- В шапке, пока не ясно, вошёл ли человек, — круглое место под аватар (кнопка «Войти» не мигает у вошедших).
- Признаки в хранилище: `loaded` (общие данные есть), `authReady` (известно про вход), `mineReady` (свои папки и подписки).
- Лента не ждёт ответов на отзывы — они догружаются следом. Зависший запрос обрывается через 5 с (дальше — 10/15/20 с) и повторяется.
- Полоска категорий (`ScrollRow`): ровно по краю ленты; на компьютере стрелки ‹ › и колесо мыши (над полоской колесо листает только её, страница не крутится), затухание у краёв. Заглушка — таблетки до края и кружок стрелки.
- Окна (вход, создание) не сдвигают страницу: при открытии окна вместо пропавшей полосы прокрутки ставится такой же отступ (`Sheet.tsx`). Способ с постоянным местом под полосу (`scrollbar-gutter`) не подошёл — подложка окна не закрывала это место, светилась полоска.

## Категории, «в избранном», показы и клики; лайков нет (сделано 9 октября)

## Ускорение загрузки (сделано 8 октября)
- Лента, авторы и отзывы запрашиваются прямо из `index.html`, параллельно с загрузкой кода сайта; соединение с сервером открывается заранее (preconnect).
- Эти запросы — «простые» (`restGet` в `src/supabase.ts`: ключ в адресе, без особых заголовков), браузер не делает перед ними предварительный запрос — минус один круг до Supabase. Список запросов — `PUBLIC_QUERIES`, должен совпадать с `index.html`.
- Данные грузятся, не дожидаясь проверки входа (они одинаковы для всех).
- Последние данные запоминаются в браузере (`klubok.data.v1`): при повторном заходе лента видна сразу, свежая подгружается следом.
- Обрывы связи: данные повторяются через 0,3 / 1 / 2,5 с, картинка — до двух раз. Раньше один оборванный запрос держал ленту ~8 с.
- Новые картинки загружаются с указанием «хранить год» — браузер не переспрашивает их при повторных заходах (демо-картинки — без этого, переспрашивает).
- Замер (из-за границы, через проброс): первый заход — карточки ~1 с вместо ~1,5–2 с (и без 8-секундных зависаний), повторный — ~0,2 с вместо ~1,5 с.
- Дальше без нагрузки на сервер: в nginx держать соединения с Supabase открытыми (keepalive) — минус ~0,3 с на каждую картинку при первом показе.
