# Дизайн-система «Списки.Заметки» → для нативного приложения (Kotlin + Jetpack Compose)

Этот документ описывает визуальный язык приложения «Списки.Заметки» (Capacitor + React + Tailwind) так, чтобы его можно было **точно** воспроизвести в новом нативном Android-приложении (календарь / напоминания с виджетами).

Состав папки `design-system/`:

| Файл | Что это |
|---|---|
| `DESIGN_SYSTEM.md` | этот документ: принципы, токены, компоненты, поведение, перевод в Compose |
| `design-tokens.json` | все числовые значения (цвета, размеры, радиусы, шрифты, анимации) в машинно-читаемом виде |
| `RUSTORE_REVIEW_AND_UPDATES.md` | окно оценки RuStore, обновление внутри приложения, «Что нового», удалённое объявление: правила показа и код |
| `STORE_LISTING_GUIDE.md` | принципы скриншотов и описания для карточки в RuStore (без привязки к тематике) |
| `screens/*.png` | эталонные скриншоты живого приложения, 390×868 dp в масштабе ×2 (780×1736 px), светлая и тёмная тема |
| `ref.html` | служебная страница, которой сняты скриншоты (для нового проекта не нужна) |

**Как пользоваться в новом проекте.** Скопировать папку `design-system/` в корень нового репозитория и в первом сообщении нового чата написать: «Дизайн — строго по `design-system/DESIGN_SYSTEM.md` и `design-tokens.json`, сверяйся со скриншотами в `design-system/screens/`». Скриншоты — главный арбитр: если текст и картинка расходятся, прав скриншот.

**Единицы.** В исходнике — CSS px. В Compose: **1 px = 1 dp**, размеры шрифта — **1 px = 1 sp**. Все цифры ниже уже можно подставлять как `.dp` / `.sp`.

**Что сознательно НЕ входит — форма иконки сущности.** У каждого приложения своя фирменная форма иконки сущности (у «Списков» — «бирка» с вырезом, `ListIconView`). Дизайн-система эту форму **не задаёт**: везде, где ниже написано «иконка сущности», подставляется форма, принятая в конкретном приложении. Задаются только размеры, градиент цвета сущности, белый символ внутри и поведение (выбор, карандаш, выделение). Иконки-плашки в строках меню и действий (7.13, 7.10) — другое: это элементы интерфейса, а не иконки сущностей, и их скруглённый квадрат остаётся частью системы.

## 1. Принципы (характер дизайна)

1. **Спокойный «стеклянный» минимализм.** Фон — почти белый (`#F5F7FA`) или почти чёрный с бирюзовым подтоном (`#070D12`). Поверх — полупрозрачные «стеклянные» плашки с тонкой обводкой 1 dp. Никаких тяжёлых теней на обычных карточках.
2. **Один фирменный акцент — бирюза → циан.** Градиент `#14B8A6 → #0891B2` (135°) — только для главных действий: FAB, основная кнопка, кнопка «отправить», иконки-плашки в меню. Всё остальное — нейтральное.
3. **Иерархия текста — размером и жирностью, а не серостью.** Важная особенность: классы «secondary / muted / faint» в приложении **переопределены на основной цвет текста** (`index.css`: `.text-muted { color: var(--text-primary) }`). То есть подписи, описания, счётчики, неактивные вкладки — того же цвета, что и заголовки, но мельче (12 sp) и тоньше (400). Серые токены `textMuted/textFaint` в токенах есть, но в интерфейсе почти не используются. Это даёт контрастный, «чистый» вид. **Соблюдать!**
4. **Скругление 16 dp — основное.** Карточки, кнопки, поля, пункты, квадратные иконки-кнопки. Круглые — только кнопки внутри строки ввода, переключатель, «таблетки»-уведомления, кнопка закрытия шторки.
5. **Мягкий фон с подсветкой.** На корне экрана — два размытых радиальных пятна бирюзы (сверху по центру и справа снизу) и лёгкий «шум» (раздел 5).
6. **Тактильность.** Каждое нажатие — уменьшение до 0.96 за 100 мс и (если включено) лёгкая вибрация.
7. **Всё снизу, под большой палец.** Нижнее меню, FAB справа внизу, строка ввода внизу, все диалоги — нижние шторки (bottom sheet). Центральных диалогов (AlertDialog) нет — подтверждения тоже шторкой.
8. **Две темы равноправны:** светлая, тёмная, «системная» (по умолчанию). Каждый экран проектируется сразу в обеих.

### 2.2 Вариант без размытия (рекомендуется для Compose по умолчанию)

В приложении есть «фолбэк» для старых WebView без `backdrop-filter`. Он же — **лучший способ в Compose**, где настоящее размытие фона дорого и доступно только с Android 12. Поверхности становятся непрозрачными, обводка — чуть заметнее:

| Токен | Светлая | Тёмная |
|---|---|---|
| `surface`, `surfaceStrong`, `surfaceCard`, `surfaceInput`, `elevated` | `#FFFFFF` | `#0F1B23` (strong/input: `#0A1219`, elevated: `#16252C`) |
| `borderSubtle` | `rgba(15,23,42,.15)` | `rgba(255,255,255,.12)` |
| `borderStrong` | `rgba(15,23,42,.22)` | `rgba(255,255,255,.18)` |
| `activeTab` | `rgba(20,184,166,.30)` | `rgba(20,184,166,.30)` |

Почему: полупрозрачный белый поверх светло-серого фона без размытия выглядит **серым** и сливается с фоном; чистый белый + обводка 15% читается отлично. Визуально на скриншотах разница с «настоящим стеклом» минимальна, потому что фон под карточками почти однотонный.

## 4. Форма, отступы, тени

### Радиусы
| Токен | dp | Где |
|---|---|---|
| `xs` | 6 | «таблетка» количества, бейдж времени на фото |
| `sm` | 12 | пункты контекстного меню, сегменты внутри переключателя, вкладки нижнего меню, плитки цвета, фото-миниатюры |
| **`md`** | **16** | **карточки, кнопки, поля, пункты, иконки-кнопки, нижнее меню, строки меню, иконки-плашки 40 dp** |
| `lg` | 22 | «пилюля» строки ввода внизу экрана |
| `xl` | 24 | верхние углы шторки |
| `full` | круг | кнопки в строке ввода, FAB-уведомления, переключатель, кнопка закрытия шторки |

FAB — **квадрат со скруглением 16**, не круг.

### Отступы (сетка 4 dp)
- Поля экрана: списки/карточки — **12** по горизонтали; настройки и шапки вкладок — **16**.
- Промежуток между карточками: **8** (компактный вид 6, крупный 12). Между пунктами внутри открытого списка — **4**.
- Между секциями настроек — **16**; от заголовка секции до содержимого — **8**; заголовок секции сдвинут внутрь на 4.
- Внутренний отступ карточки — **12** (крупные — 16).
- Пункт списка — **12** по горизонтали, **10** по вертикали.
- Шторка: **16** по бокам, **24** снизу.
- Снизу у прокручиваемого списка — запас **96**, чтобы FAB не перекрывал последний элемент.

### Тени
- Обычные «стеклянные» карточки — **без тени**, только обводка 1 dp `borderSubtle`.
- Плашки поверх цветного фона (пункты открытого списка): светлая `0 1 3 rgba(15,23,42,.16)`, тёмная `0 1 2 rgba(0,0,0,.5)` — в Compose ≈ `elevation 1–2 dp` с цветом тени.
- FAB и «таблетка»-уведомление — `shadow-lg` (≈ 6–8 dp).
- Контекстное меню — `shadow-2xl` (≈ 16–24 dp, мягкая).
- Шторка — тень вверх `0 -8 32 rgba(0,0,0,.4)`.

## 5. Фон экрана (подсветка + шум)

Под всем контентом, на всю высоту окна:
1. Заливка `background`.
2. Эллиптический радиальный градиент **сверху**: центр (50%, −10%), радиусы 80% ширины × 50% высоты, от `glowTop` к прозрачному.
3. Эллиптический радиальный градиент **справа снизу**: центр (100%, 100%), радиусы 60% × 40%, от `glowBottomRight` к прозрачному.
4. Поверх всего (над контентом, не ловит касания) — «шум» fractal noise (baseFrequency 0.85, 2 октавы, альфа 4%), режим наложения overlay, прозрачность 0.15 в светлой / 0.5 в тёмной. **Эффект почти незаметен** — в Compose его можно опустить или положить маленькую PNG-текстуру шума с `BlendMode.Overlay`.

```kotlin
@Composable
fun AppBackground(content: @Composable () -> Unit) {
    val c = AppTheme.colors
    Box(Modifier.fillMaxSize().background(c.background).drawBehind {
        val w = size.width; val h = size.height
        // Эллиптическое пятно: рисуем круг и сжимаем по вертикали вокруг его центра.
        fun glow(color: Color, cx: Float, cy: Float, rx: Float, ry: Float) =
            scale(scaleX = 1f, scaleY = ry / rx, pivot = Offset(cx, cy)) {
                drawCircle(Brush.radialGradient(listOf(color, Color.Transparent), Offset(cx, cy), rx),
                    radius = rx, center = Offset(cx, cy))
            }
        glow(c.glowTop, cx = w * 0.5f, cy = -0.1f * h, rx = w * 0.8f, ry = h * 0.5f)      // сверху по центру
        glow(c.glowBottomRight, cx = w, cy = h, rx = w * 0.6f, ry = h * 0.4f)             // справа снизу
    }) { content() }
}
```
(Точность эллипса не критична — главное: мягкое бирюзовое свечение у верхнего края и едва заметное у правого нижнего угла. Сверяйтесь со скриншотами `*-dark.png`, там оно заметнее.)

## 6. «Стекло» в Compose

`glass` = фон `surface` + размытие фона 24 dp с насыщенностью 180% + обводка 1 dp `borderSubtle`.
`glass-strong` = `surfaceStrong` + размытие 32 + обводка `borderStrong`.

Рекомендация:
- **По умолчанию** — без размытия, непрозрачные цвета из раздела 2.2. Выглядит так же на однотонном фоне и работает на всех версиях Android.
- **Опционально** на Android 12+ — библиотека [Haze](https://github.com/chrisbanes/haze) (`dev.chrisbanes.haze`) для настоящего размытия под нижним меню и шторкой, с полупрозрачными цветами из 2.1.

```kotlin
fun Modifier.glass(shape: Shape = RoundedCornerShape(16.dp), strong: Boolean = false) = composed {
    val c = AppTheme.colors
    this.clip(shape)
        .background(if (strong) c.surfaceStrong else c.surface)
        .border(1.dp, if (strong) c.borderStrong else c.borderSubtle, shape)
}
```

## 7. Компоненты

Для каждого компонента: размеры → цвета → состояния → поведение. Скриншоты-эталоны указаны в скобках.

### 7.1 Нижнее меню (все главные экраны)
- Это **плавающая «пилюля»**, а не панель во всю ширину до края экрана. Фон пилюли НЕ уходит под системную панель навигации.
- **Положение по вертикали (важно!):** нижний край пилюли стоит **над системной панелью навигации** (полоска жестов или три кнопки). Отступ снизу = `max(высота системной панели, 6 dp)`. То есть при жестах пилюля — сразу над полоской жестов, при трёх кнопках — сразу над кнопками; если панели нет — 6 dp от края экрана.
- Отступы по бокам — **8 dp** от краёв экрана.
- **Высота пилюли — 54 dp:** вкладка 44 (6 + иконка 20 + 2 + подпись 10 + 6) + внутренний отступ 4 сверху и снизу + обводка 1 dp.
- Сам бар — `glass`, радиус **16**, внутренний отступ **4**, вкладки распределены равномерно (weight 1).
- Типичные ошибки, из-за которых меню «проседает» ниже, чем в «Списках»:
  - стандартный `NavigationBar` из Material 3 или `Scaffold(bottomBar = …)`: у них фон тянется до края экрана, а отступ системной панели уходит **внутрь** бара;
  - `navigationBarsPadding()` применён внутри фона пилюли, а не снаружи;
  - отступ системной панели не учтён совсем.

```kotlin
Box(
    Modifier
        .fillMaxWidth()
        .windowInsetsPadding(WindowInsets.navigationBars.union(WindowInsets(bottom = 6.dp))) // max(панель, 6dp) — СНАРУЖИ пилюли
        .padding(horizontal = 8.dp)
) {
    Row(Modifier.fillMaxWidth().height(54.dp).glass(RoundedCornerShape(16.dp)).padding(4.dp)) { /* вкладки weight(1f) */ }
}
```
- Прокручиваемый контент над меню получает нижний отступ = высота меню + отступ снизу (+ запас под FAB), чтобы последний элемент не прятался.
- Вкладка: колонка, иконка 20 + подпись 10 sp/600, промежуток 2, вертикальный отступ 6, радиус 12.
- **Активная:** подложка `activeTab` + обводка 1 dp `rgba(45,212,191,.30)` на всю вкладку (радиус 12), иконка толщиной линии **2.4**.
- **Неактивная:** без подложки, толщина линии иконки **1.8**; цвет текста тот же `textPrimary`.
- Нажатие: лёгкая вибрация только при смене вкладки.
- В «Списках» 3 вкладки: Избранное (Star), Все списки (ListChecks), Настройки (Settings). (`favorites-*.png`, `lists-*.png`)

### 7.4 FAB (создать)
- **56×56**, радиус **16**, градиент `#14B8A6 → #0891B2` 135°, иконка Plus 26 белая, толщина 2.4, тень ≈ 8 dp.
- Позиция по умолчанию: справа 16, снизу — **над верхним краем нижнего меню** с зазором 12. Высота меню учитывает системную панель (7.1).
- Короткое нажатие → средняя вибрация → шторка «Что создать?».
- **Перетаскивание — обязательно:**
  1. Зажать кнопку на **420 мс**. Движение пальца до этого момента не отменяет удержание.
  2. Через 420 мс — **средняя вибрация**, кнопка увеличивается до **scale 1.05**. С этого момента она едет за пальцем, сохраняя точку, за которую её взяли (без «прыжка» центра под палец).
  3. Кнопку можно поставить **в любое место экрана**, в том числе поверх нижнего меню. Ограничение одно: от краёв окна не ближе **8 dp** (`x ∈ [8, ширина − 56 − 8]`, `y ∈ [8, высота − 56 − 8]`).
  4. Отпустили — scale возвращается к 1. Позиция (левый верхний угол, в dp) **сохраняется навсегда** (DataStore/SharedPreferences) и восстанавливается при следующем запуске. При восстановлении снова прижимается к границам, если экран стал меньше: поворот, другой телефон.
  5. Отпускание после перетаскивания **не считается нажатием**: шторка не открывается.
  6. Прилипания к краям и кнопки «вернуть на место» нет: где поставили, там и стоит.
- В Compose:
  - `pointerInput` с `awaitEachGesture`: ждём `withTimeoutOrNull(420)` отпускания; не отпустили — режим перетаскивания;
  - позиция в `Animatable`/`mutableStateOf<Offset>`, кнопка рисуется через `Modifier.offset { IntOffset(x, y) }` в `Box(Modifier.fillMaxSize())` поверх всего экрана;
  - вибрация через `LocalHapticFeedback.current.performHapticFeedback(HapticFeedbackType.LongPress)`.

## 8. Цветной фон открытого экрана и «цвет плашек»

Открытый список рисуется поверх **своего фона**, окрашенного в цвет типа. Для нового приложения это хорошо ложится на экран дня / календаря / категории.

**Базовая подложка** (есть у всех фонов с узором): линейный градиент 165° от `g1` к `g2`:
- светлая: `g1 = mix(#F5F7FA, светлый_цвет_типа, 0.32)`, `g2 = mix(#F5F7FA, тёмный_цвет_типа, 0.08)`;
- тёмная: `g1 = mix(#070D12, тёмный_цвет_типа, 0.24)`, `g2 = mix(#070D12, светлый_цвет_типа, 0.07)`.

`mix(a, b, t)` — линейное смешение каналов RGB: `a·(1−t) + b·t`.

**Цвет плашек** (пункты, сообщения, итог) — выбирается отдельно для светлой и тёмной темы:

| Режим | Светлая | Тёмная |
|---|---|---|
| «В цвет списка» (по умолчанию) | фон `mix(светлый, тёмный, 0.5)`, текст и акценты **белые**, обводка «таблетки» белый 60% | фон `mix(#0B141B, тёмный, 0.5)`, текст `#F1F5F9`, акцент `#14B8A6` |
| «В цвет темы» | фон `#FFFFFF`, текст `#0F172A`, акцент `#14B8A6` | фон `#1A2530`, текст `#F1F5F9`, акцент `#14B8A6` |

Строка ввода всегда: светлая `#FFFFFF`, тёмная `#1A2530`. Тень плашек — раздел 4. «Таблетки» поверх фона: светлая `rgba(255,255,255,.85)` с тёмным текстом, тёмная `rgba(0,0,0,.4)` со светлым.

## 12a. Стартовый экран (splash) с логотипом

При запуске сначала показывается **логотип приложения по центру на фоне темы**, затем плавно появляется интерфейс. Это обязательная часть.

- Механизм: **AndroidX SplashScreen API** (`androidx.core:core-splashscreen`). В Compose-приложении так же, как в «Списках».
- Тема запуска у `MainActivity` в манифесте (`android:theme="@style/Theme.App.Starting"`):
  ```xml
  <style name="Theme.App.Starting" parent="Theme.SplashScreen">
      <item name="windowSplashScreenBackground">@color/windowBg</item>
      <item name="windowSplashScreenAnimatedIcon">@drawable/logo_splash_padded</item>
      <item name="postSplashScreenTheme">@style/Theme.App</item>
  </style>
  ```
- **Фон** — цвет фона темы: `values/colors.xml` → `windowBg = #F5F7FA`, `values-night/colors.xml` → `windowBg = #070D12`. Никаких белых или чёрных «вспышек» между splash и приложением.
- **Иконка** — логотип нового приложения, PNG **960×960** (или vector).
  - Сам знак занимает только **центральную треть** (~320×320), остальное — прозрачные поля. Иначе Android 12+ обрежет его круглой маской.
  - Знак — в фирменном градиенте `#2DD4BF → #0891B2` с белым символом внутри.
- В `MainActivity.onCreate`:
  - **до** `super.onCreate()` вызвать `installSplashScreen()`;
  - до `super.onCreate()` покрасить окно в цвет фона темы: `window.setBackgroundDrawable(ColorDrawable(bg))`. Первый кадр должен быть сразу нужного цвета;
  - `WindowCompat.setDecorFitsSystemWindows(window, false)` — edge-to-edge, системные панели прозрачные.
- **Тема приложения, а не только системная:** если пользователь выбрал «Светлая»/«Тёмная» внутри приложения, splash тоже должен быть в ней.
  - На Android 12+: `UiModeManager.setApplicationNightMode(...)` при смене темы, чтобы система запомнила выбор для следующего запуска.
  - Также `AppCompatDelegate.setDefaultNightMode(...)` до `super.onCreate()`.
- **Сколько держать:** `splashScreen.setKeepOnScreenCondition { !ready }`, где `ready` — загружены настройки (тема) и первые данные. Нативное приложение стартует быстро, и логотип мелькнёт на долю секунды. Чтобы его было видно как в «Списках» (там ~0.5–1 с), держать **не меньше ~600 мс** от старта.
- Если запускать из Android Studio кнопкой Run, на Android 12+ иконка splash может не показаться. Проверять запуском **с иконки на рабочем столе**.

## 14. Фоны-узоры («дудлы») — необязательно, на всякий случай

Узорный фон, как обои в мессенджерах: контурные иконки Lucide разного размера и поворота, хаотично и **бесшовно** разбросанные по квадратному тайлу, плюс мелкие точки/звёздочки в промежутках. Перекрашивается кодом под цвет типа и тему, без картинок.

**Алгоритм (для точного повторения):**
1. Тайл **T = 380 dp**. Генератор псевдослучайных чисел — mulberry32, seed — FNV-1a-хэш строки id фона (`hash = 2166136261; hash = (hash xor charCode) * 16777619`). Раскладка детерминированная и кэшируется.
2. **Иконки:** 5000 попыток; размер `s = 19 + r·15` (19–34 dp), радиус столкновения `s·0.6`, поворот `(r − 0.5)·60°` (±30°), позиция случайная в тайле. Ставим, если не ближе `rad₁ + rad₂ + 5` ни к одной уже поставленной (расстояние считается **на торе**: `dx = min(|dx|, T − |dx|)`, так же dy — это делает узор бесшовным).
3. **Назначение иконок:** обходим точки в случайном порядке; для каждой перебираем иконки набора, отсортированные по «наименее использованная» (при равенстве — случайно); берём первую, чей ближайший двойник дальше **150 dp**; если такой нет — ту, у которой `min(дистанция до двойника, 1000) − использований·8` максимальна.
4. **Заполнители:** 4000 попыток; размер 4–9 dp, поворот 0–90°, зазор 6; фигуры: кружок, 4-лучевая звезда, 5-лучевая звезда — **залитые** тем же цветом.
5. **Отрисовка:** каждая точка рисуется 9 раз со сдвигами `{−T, 0, T}²` (только если попадает в `[−40, T+40]`), масштаб иконки `s/24`, толщина линии в итоге **1.4 dp**, скруглённые концы. Прозрачность задаётся **на всю группу** (не на цвет линии), иначе на пересечениях линии темнеют.
6. **Цвет линий:** светлая тема — тёмный цвет типа, прозрачность **0.17**; тёмная — светлый цвет типа, **0.15**.
7. Под узором — базовая подложка из раздела 8.

**Другие виды фона:**
- **Клетка:** шаг 22 dp, линии 1 dp; цвет светлая — тёмный цвет типа 14%, тёмная — светлый 13%.
- **Линейка:** шаг 28 dp, линия 1 dp (светлая — тёмный цвет типа 16%, тёмная — светлый 16%); вертикальная линия полей на 30 dp, толщина 1.5, светлая `rgba(225,29,72,.35)`, тёмная `rgba(251,113,133,.35)`.
- **Акварель:** фон светлая `#F7F8FB` / тёмная `#0B1218`; четыре круглых радиальных пятна: (18%, 22%) светлый цвет 30% → прозрачный на 42%; (85%, 35%) тёмный 23% → 38%; (30%, 80%) тёмный 21% → 40%; (80%, 88%) светлый 24% → 36%.
- **Своё фото:** картинка cover + сверху заливка цветом фона темы с прозрачностью 0.35 (регулируется), чтобы плашки читались.
- **Без фона:** просто `background`.

Наборы иконок (по темам) — в `src/lib/backgrounds.ts`, массив `BACKGROUNDS`. Для календаря логично сделать свои наборы: «Праздники», «Времена года», «Спорт», «Учёба» и т.п. В Compose тайл удобно отрисовать один раз в `ImageBitmap` (Canvas + `PathParser` для путей Lucide) и залить `ShaderBrush(ImageShader(bitmap, TileMode.Repeated, TileMode.Repeated))`.

Миниатюры выбора фона в «Списках»: сетка квадратных плиток радиус 16, узор в масштабе ×0.5, выбранная — обводка 2 dp акцентом.
